# SPEC — Рация-торг с диспетчером (голосовая механика)

_Дизайн 2026-06-19. Хоррор-комедийная фишка: посреди аварии игрок по рации торгуется за оплату, диспетчер с жильцами его динамят. Голос — офлайн (распознавание + синтез), в релиз идёт чисто._

---

## Фантазия игрока
Дом разносит, паника, и тут ты жмёшь рацию: «Диспетчер, тут пиздец, проси тройную оплату у жильцов!» — пауза, помехи — диспетчер: «Жильцы послали нас нахуй, работай давай». Смех сквозь страх. Чем сильнее разнесён дом / выше опасность — тем больше у тебя плечо в торге (риск ↔ награда).

## Плагины (всё офлайн, georgy.dev)
- **Runtime Speech Recognizer** (Whisper) — распознавание речи игрока, рус, офлайн, GPU.
- **Runtime Text To Speech** (Piper/Kokoro) — голос диспетчера, рус, офлайн.
- **Runtime Audio Importer** — компаньон, проигрывает синтез (нужен обоим).
- (опц., позже) **Runtime MetaHuman Lip Sync** — если диспетчер станет видимым персонажем.

## Принцип распознавания — ИНТЕНТ, не дословно
Свободную фразу целиком парсить ненадёжно. Ловим **интент по ключам** (у Recognizer есть Voice Activity + Command Detection):
1. **Push-to-talk** на клавише рации (зажал — слушает, отпустил — обрабатывает). Без удержания микрофон не активен (приватность + нет ложных срабатываний).
2. Whisper → текст → нормализация (lower, убрать пунктуацию) → матч по словарю ключей.
3. Говорить можно как угодно (хоть матом) — реагируем только на пойманный ключ.
4. Не распозналось / нет ключа → диспетчер «помехи, повтори» (в тему рации, не штраф).

### Словарь интентов (рус, расширяемый)
| Интент | Ключи (вхождение подстроки) | Что делает |
|---|---|---|
| `REQUEST_RAISE` | тройн, больше, подними, доплат, оплат, бабк, денег | торг за повышение выплаты |
| `CALL_BACKUP` | подмог, помощь, эвакуац, забери, вытащ | запрос подмоги/эвакуации |
| `REPORT_OK` | готов, закончил, всё норм, починил, сделал | доклад о завершении |
| `CANCEL` | отмена, забей, похер, проехали | отмена запроса |
| `INSULT` (пасхалка) | сам дурак, иди ты, нахуй | диспетчер огрызается, без эффекта |

## Цикл торга (REQUEST_RAISE) — ядро
1. Игрок зажал рацию, сказал интент `REQUEST_RAISE`.
2. SFX: щелчок рации + помехи (`SC_Radio` уже собран).
3. Диспетчер «звонит жильцам» (пауза 1.5–3 с, помехи).
4. **Взвешенный рандом исхода**, веса зависят от `Leverage` (см. ниже).
5. Диспетчер озвучивает исход (TTS) + применяется эффект к выплате/морали.
6. **Кулдаун** на повторный торг (анти-спам), напр. 60 с или 1 на аварию.

### Leverage (плечо торга) = f(опасность, разрушения)
`Leverage` 0..1, считается из текущего состояния забега:
- доля активных аварий (горит/газ/потоп/ток) от макс,
- степень разрушений дома (если есть метрика destruction),
- паника бригады / время на объекте.
Чем выше Leverage → тем выше шанс на согласие и больше множитель.

### Таблица исходов (веса сдвигаются по Leverage)
| Исход | Множитель выплаты | Доп. эффект | Вес при low / high Leverage |
|---|---|---|---|
| Согласились | ×3.0 | — | 5% / 35% |
| Контра ×1.5 | ×1.5 | — | 25% / 40% |
| Послали | ×1.0 | +паника, −мораль | 50% / 20% |
| Диспетчер взял кусок | ×1.5, но −20% тебе | комедийный | 20% / 5% |

(числа — стартовые, тюнятся плейтестом)

### Пул реплик диспетчера (TTS, рус) — расширять
- Согласились: «Жильцы в панике, платят сколько скажешь.» / «Договорился, тройная — но шевелись.»
- Контра: «Дают полтора, бери пока дают.» / «Больше не выбьешь, полтора и точка.»
- Послали: «Жильцы послали нас нахуй, работай давай.» / «Сказали — за такие деньги пусть горит.»
- Кусок диспетчеру: «Норм, но мой процент сверху, не благодари.»
- Помехи: «Тебя не слышно, повтори.» / «Connection… пшшш… повтори по рации.»
- INSULT: «Сам справляйся тогда, умник.»

Подстановка чисел в TTS на лету (сумма/множитель) — TTS синтезирует любой текст офлайн.

## Привязка к экономике
- Множитель применяется к выплате за забег (`SPEC_Shop_Progression.md` — система оплаты).
- «Послали» → штраф к морали/панике (через `VitalsComponent`), небольшой, ради комедии напряжения.
- Лог торга показать в HUD-«акте работ» строкой («Диспетчер: ×1.5»).

## Точки в коде (verify по факту)
- **Рация/вызов:** `ACallBoard` (уже есть) — точка входа push-to-talk и приёма ответа; либо предмет-рация в руках.
- **Новый компонент** `URadioHaggleComponent` (на персонаже/контроллере): состояние (idle/listening/awaiting), кулдаун, расчёт Leverage, выбор исхода, вызов TTS.
- **Распознавание:** обёртка над Runtime Speech Recognizer (старт по PTT-down, стоп+парс по PTT-up).
- **Синтез:** обёртка над Runtime TTS + Audio Importer → проиграть на рации (2D или из меша рации).
- **Экономика:** применить множитель к payout-структуре забега (где считается оплата).
- **Кооп:** торг инициирует один игрок; исход — серверно-авторитетный (рандом на сервере), реплика всем; TTS играет у всех.

## MVP → расширение
- **MVP:** только `REQUEST_RAISE` + 4 исхода + фикс. пул реплик + кулдаун. Leverage = простая формула (число активных аварий).
- **Позже:** остальные интенты (backup/report/cancel), Leverage от разрушений, процедурные реплики с именами/адресами, разные «характеры» диспетчера.
- **Фоллбэк без микрофона:** колесо рации с текстовыми командами (тот же бэкенд интентов) — для тех, у кого нет/не хочет микрофон. Голос — поверх, не вместо.

## РАСШИРЕНИЕ: общая рация + диспетчер-подслушка (ключевая фишка)
Рация **общая** — игроки болтают между собой по ней (proximity + радио-канал), а **диспетчер всегда на канале и слышит всё**. Не только прямые команды — он реагирует на то, что вы между собой говорите. Эмерджентный юмор: вы орёте напарнику, а диспетчер влезает с комментарием.

### Два режима слушания
| Режим | Триггер | Поведение |
|---|---|---|
| **Команда** (deliberate) | Push-to-talk на канал диспетчера | Точный интент → торг/подмога (основной цикл выше) |
| **Подслушка** (ambient) | Любая передача игрока по общей рации | Лёгкий keyword-spotting → диспетчер РЕДКО влезает репликой |

### Как не превратить в спам (важно)
- Whisper НЕ гоняем постоянно — только пока игрок **жмёт рацию и передаёт** (есть аудио-поток). VRAM/перф под контролем (tiny/base модель на ключи).
- Подслушка-реакции **на кулдауне + по вероятности** (напр. глоб. кулдаун 30–45 с, шанс 20–30% на пойманный триггер). Диспетчер — приправа, не диктор.
- «Настроение» диспетчера: не повторять одну реплику подряд, ротация пула.

### Триггеры подслушки (примеры)
| Услышал в эфире | Диспетчер влезает (TTS) |
|---|---|
| паника: «горим / тонем / бежим / помогите» | «Да слышу я, не ори. Работайте.» |
| деньги: «бабки / оплата / премия» | «Размечтались. Сначала почините.» |
| мат в эфире | «Полегче на канале, тут запись.» |
| упомянули монстра / «оно тут» | «…повторите? Кто там у вас?» *(зловеще)* |
| тишина в эфире долго | «Бригада, доложите обстановку.» |

### Архитектура (кооп)
- **Общий канал = voice-chat плагин** (Cross-Platform Voice Chat / Fire Chat PRO) — бэкбон. Recognizer слушает тот же mic-поток локально у говорящего.
- Игрок передаёт → у него локально Whisper → распознанный текст/интент шлётся **на сервер** → сервер решает (кулдаун/вероятность/исход) → реплика диспетчера (TTS) проигрывается **у ВСЕХ на канале**. Все слышат, как диспетчер влез — в этом и соль (общий момент).
- TTS-аудио: генерим у сервера/одного клиента, реплицируем событие «диспетчер сказал X» → каждый клиент синтезирует/проигрывает локально (текст реплики мал, синтез офлайн быстрый).
- ⚠️ Это поднимает приоритет **voice-chat плагина** — без общей рации вся фишка не работает. (Обновить `СКАЧАТЬ.md`: Voice Chat → ⭐.)

## Риски / заметки
- Точность Whisper на шумах/акценте → именно поэтому интент-ключи, а не дословный парс; всегда есть «повтори».
- Производительность: Whisper тянет GPU (у нас RTX 5060 8ГБ — следить за VRAM, гейтить размер модели; tiny/base модели хватит для ключей).
- Тон: мат/чёрный юмор — часть идентичности игры; вынести в настройку «цензура вкл/выкл» если понадобится для возрастного рейтинга.
- Локализация: рус-голоса есть у обоих плагинов; англ-версия — те же интенты на англ-ключах.
